# Krama Android app (TWA)

A **Trusted Web Activity** — a thin Android wrapper around the Krama PWA
(`https://kramajob.com`). It runs the site full-screen with no browser UI, is
installable from the Play Store, and shares the same login/session as the website.
No separate app codebase to maintain: whatever ships on the web ships in the app.

- **Package id:** `com.kramajob.twa`
- **Generated by:** [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) from `twa-manifest.json`
- **Domain verification:** `https://kramajob.com/.well-known/assetlinks.json`

## Files

| File | Purpose | Committed? |
|------|---------|-----------|
| `twa-manifest.json` | Bubblewrap config (name, colors, icons, shortcuts, version) | ✅ yes |
| `app/`, `gradle/`, `build.gradle`… | Generated Android project | ✅ yes |
| `android.keystore` | **Upload signing key — SECRET** | ❌ gitignored |
| `.signing-password.txt` | keystore/key password | ❌ gitignored |
| `app-release-bundle.aab` | the build you upload to Play | ❌ gitignored |
| `app-release-signed.apk` | for direct install / testing | ❌ gitignored |

> ⚠️ **Back up `android.keystore` + its password somewhere safe** (a password
> manager). It's the upload key. If you enroll in Play App Signing (recommended,
> and the default) a lost upload key can be reset via Play support, but keep it anyway.

## Prerequisites (already set up on this machine)

- Node + `npx @bubblewrap/cli`
- JDK 17 — `~/.bubblewrap/config.json` points `jdkPath` at `…/zulu-17.jdk`
- Android SDK at `~/Library/Android/sdk` (licenses accepted)

## Rebuild (after a version bump or icon/name change)

1. Bump `appVersionCode` (integer, +1 every upload) and `appVersionName` in `twa-manifest.json`.
2. From this folder:

```bash
export BUBBLEWRAP_KEYSTORE_PASSWORD="$(cat .signing-password.txt)"
export BUBBLEWRAP_KEY_PASSWORD="$(cat .signing-password.txt)"
npx @bubblewrap/cli build --skipPwaValidation
```

Outputs `app-release-bundle.aab` (upload this) and `app-release-signed.apk` (test this).

## Test on a device / emulator

```bash
# plug in a phone with USB debugging, or start an emulator, then:
~/Library/Android/sdk/platform-tools/adb install -r app-release-signed.apk
```

On first launch the app calls out to `assetlinks.json`. If it verifies, there is **no
URL bar**. If you still see one, the fingerprint in `assetlinks.json` doesn't match the
signing key — see below.

## Publish to Google Play (one-time, needs your Play Console account)

1. **Play Console → Create app** → name "Krama", app, free.
2. **Create a release** (Internal testing first) → upload `app-release-bundle.aab`.
3. Keep **Play App Signing** enabled (default). Google now holds the *app-signing key*
   and re-signs your app — its fingerprint differs from the upload key.
4. **Play Console → Test and release → App integrity → App signing** → copy the
   **SHA-256 of the "App signing key certificate"**.
5. Add that fingerprint to `krama/.well-known/assetlinks.json` (keep the upload-key one
   too) and redeploy it (see below). Both fingerprints can coexist in the array.
6. Fill the store listing (icon, screenshots, description, privacy policy →
   `https://kramajob.com/privacy`), set content rating + data-safety, then roll out.

## Deploying `assetlinks.json`

It must be served at the **origin root**: `https://kramajob.com/.well-known/assetlinks.json`
as `application/json`. The repo copy is `krama/.well-known/assetlinks.json`; deploy it to
`~/kramajob.com/.well-known/assetlinks.json` on the server. Verify:

```bash
curl -s https://kramajob.com/.well-known/assetlinks.json
```

Google's tester: https://developers.google.com/digital-asset-links/tools/generator
